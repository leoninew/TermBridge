# 快捷方式卡片拖拽排序
最后修改时间: 2026-06-18 09:03:27

- Flow mode: light
- Stage: Requirement
- Review status: Accepted
- Date: 2026-06-18

## Background

`/shortcuts` 页面当前已经按运行环境分组展示快捷方式卡片，且前端仓库里已经引入了 `vue-draggable-plus` 相关拖拽能力。现阶段快捷方式卡片支持创建、编辑、删除和创建会话，但不能在同组内调整展示顺序。

本需求只关注快捷方式卡片的拖拽排序交互，不改变快捷方式本身的创建、编辑、删除和创建会话语义。

## Goal

1. 为 `/shortcuts` 页面里的快捷方式卡片增加拖拽排序能力。
2. 拖拽范围只限于当前分组内，不能跨组拖动。
3. 排序结果需要持久化，并在刷新后保持。
4. 保持当前卡片上的创建会话、编辑、删除等操作可用。
5. 保持现有分组展示方式和整体视觉风格不变。

## Non-goal

1. 不实现跨组拖动。
2. 不改变快捷方式分组方式。
3. 不重新设计 `/shortcuts` 页面布局。
4. 不扩展快捷方式的创建、编辑、删除语义。
5. 不在本需求里引入新的快捷方式数据模型。

## User scenarios

1. 用户在同一组快捷方式卡片之间拖动某个卡片，把常用项排到前面。
2. 用户尝试把卡片拖到其他组时，系统不允许跨组移动。
3. 用户拖动卡片时，卡片上的按钮仍然可以正常点击，不会误触发拖拽。
4. 用户排序后，页面展示顺序能够反映新的排列结果。

## Acceptance

1. `/shortcuts` 页面中的快捷方式卡片支持拖拽排序。
2. 拖拽只能在同一组内生效，不能跨组移动。
3. 卡片上的主要操作按钮在拖拽能力启用后仍可正常使用。
4. 拖拽过程有清晰的视觉反馈，用户能看出当前正在排序。
5. 排序结果不会影响快捷方式的分组归属。
6. 排序结果持久化到快捷方式存储中，刷新或重新进入 `/shortcuts` 后保持。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

1. 先沿用现有拖拽依赖和前端实现模式。
   - Why: 项目已经引入了拖拽能力，优先复用现有方案，降低实现成本。
2. 拖拽范围限制在同组内。
   - Why: 用户明确要求“只能本组拖拽”，避免跨组移动带来的语义变化。
3. “组”定义为当前页面按运行环境划分的 Cygwin / WSL / Linux 分组。
   - Why: 用户已确认各运行环境各自组内排序，不能跨运行环境移动。
4. 排序结果需要持久化到快捷方式存储中。
   - Why: 快捷方式查询来自 `shortcuts.json` 的有序结构，用户明确要求排序当然需要持久化。
5. 保持卡片上的现有操作入口不变。
   - Why: 排序是增量能力，不应回退创建会话、编辑和删除行为。

## Risk

1. 拖拽手势可能和卡片按钮点击发生冲突，需要明确拖拽触发区域或事件隔离。
2. 持久化排序需要新增排序接口或服务能力，必须校验请求包含当前环境下所有快捷方式且不能混入其他环境的快捷方式。
3. 需要避免拖拽时误触发创建会话、编辑或删除操作。
