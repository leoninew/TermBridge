# 独立拖动排序能力

- Flow mode: standard
- Stage: Requirement
- Review status: Accepted
- Date: 2026-06-14

## Background

当前会话工作区已经包含三类可排序的用户导航对象：环境分组下的目录、目录下的会话、以及终端区域顶部的 tab。随着目录、会话和打开终端数量增加，用户需要按自己的工作流调整展示顺序，而不是只能依赖后端返回顺序或创建时间顺序。

本需求新增 3 块彼此独立的拖动排序能力，并明确使用 `vue-draggable-plus` 作为前端拖拽排序实现基础。拖动排序用于提升当前工作区导航效率，不改变会话启动、停止、删除、创建和终端运行语义。

## Goals

1. 在特定环境下的目录列表支持拖动排序。
2. 在特定目录下的会话列表支持拖动排序。
3. 终端 tab 页头支持拖动排序。
4. 三块排序区域互相独立，拖动操作只能影响当前区域内的顺序。
5. 基于 `vue-draggable-plus` 实现拖拽排序交互。
6. 保持现有会话选择、active session、终端 tab 激活、目录操作、会话操作等行为不倒退。

## Non-goals

1. 不允许跨环境拖动目录；目录只能在同一环境的目录列表内排序。
2. 不允许跨目录拖动会话；会话只能在所属目录下排序。
3. 不允许从目录/会话列表拖动到终端 tab，或从终端 tab 拖动回会话列表。
4. 不改变 session tree 后端数据结构的业务含义；如需持久化排序，只新增排序相关能力，不改变会话归属关系。
5. 不重新设计侧边栏两级分组的信息架构。
6. 不改变终端 tab 的关闭、选择、创建会话入口和 active 样式。
7. 不实现复杂的多选拖动、跨区域批量移动或拖动复制。

## User Scenarios

1. 用户在同一环境下有多个项目目录时，可以通过拖动目录调整常用目录的展示位置。
2. 用户在某个目录下有多个会话时，可以通过拖动会话调整会话的浏览顺序。
3. 用户打开多个终端 tab 后，可以拖动 tab 调整工作顺序，例如把当前关注的 tab 移到更靠前的位置。
4. 用户拖动某个环境下的目录时，其他环境下的目录顺序不受影响。
5. 用户拖动某个目录下的会话时，其他目录下的会话顺序不受影响。
6. 用户拖动终端 tab 时，左侧目录列表和会话列表顺序不受影响。

## Acceptance Criteria

1. 每个环境分组下的目录列表可以在该环境内拖动排序。
2. 目录拖动排序不会跨越环境分组，也不会改变目录所属环境。
3. 每个目录节点下的会话列表可以在该目录内拖动排序。
4. 会话拖动排序不会跨越目录，也不会改变会话所属目录或 workspace。
5. 终端 tab 页头可以在已打开 tab 范围内拖动排序。
6. 终端 tab 拖动排序不会改变左侧会话树中目录或会话的顺序。
7. 左侧目录/会话拖动排序不会改变终端 tab 页头的顺序。
8. 拖动排序过程中应有明确的拖动反馈，避免用户误以为点击或选择。
9. 点击 session 仍能打开/激活对应终端 tab；拖动 session 不应误触发打开或切换。
10. 点击终端 tab 仍能激活对应 session；拖动 tab 后 active tab 应保持为同一个 session，而不是错误切换到原位置上的另一个 tab。
11. 会话启动、停止、删除、目录删除、新建会话等现有操作入口保持可用。
12. 拖动能力基于 `vue-draggable-plus` 实现，并纳入前端依赖管理。
13. 浅色和暗色主题下拖动状态、占位状态和列表项样式保持一致且可读。
14. 目录排序和会话排序必须通过 `.termbridge/sessions.json` 持久化；刷新页面或重新加载 session tree 后应恢复用户调整后的目录/会话顺序。
15. 终端 tab 排序无需持久化；同一前端会话内 tab 顺序不应因普通选中/切换操作丢失。

## Decisions

1. 拖动排序分为 3 个独立区域：环境内目录列表、目录内会话列表、终端 tab 页头。
   - Why: 这三类对象的归属关系和用户心智不同，互相拖动会引入“移动/重归属”的语义，不属于排序。
2. 使用 `vue-draggable-plus`。
   - Why: 用户明确指定该库；其适配 Vue 3，可直接表达列表排序交互。
3. 默认优先保持当前信息架构和现有操作行为。
   - Why: 本需求只新增排序能力，不应扩大为侧边栏或终端 tab 的重新设计。

## Risks / Assumptions

1. `vue-draggable-plus` 当前不在 `web/package.json` 依赖中，后续实现阶段需要新增依赖并确认与当前 Vue/Vite/TypeScript 版本兼容。
2. 左侧会话树当前基于 Reka UI `TreeRoot`，与 draggable 组合时可能影响键盘导航、展开/折叠和选择事件，需要在 Plan 阶段设计事件隔离。
3. 终端 tab 当前基于 Reka UI Tabs，拖动 tab 时需要确保 `model-value` / active session 语义仍按 session id 而不是数组位置判断。
4. 目录和会话排序需要写入 `.termbridge/sessions.json` 的现有有序结构；Plan 阶段应避免新增排序字段或引入额外 storage。
5. 拖动手势与行内按钮 hover 操作可能冲突，需要明确按钮过滤或事件防护，避免误拖、误点。
