# 会话列表默认折叠与环境级展开控制

- Flow mode: light
- Stage: Requirement
- Review status: Accepted
- Date: 2026-06-16

## Background

会话列表面板在会话数量较多时可能产生滚动。当前界面加载后如果多个环境下的目录节点全部展开，会占用较多纵向空间，用户需要滚动才能定位当前需要关注的环境或目录。

已有会话侧边栏结构中，环境节点作为一级节点，目录或工作区作为二级节点。此次优化聚焦初始展开状态和环境级批量展开/折叠控制，减少进入页面时的视觉噪音和滚动压力。

## Goal

1. 界面加载时，有活动状态会话的目录默认展开；没有活动状态会话的目录默认折叠。
2. 环境分组保持可见，活动会话所在目录保持必要展开，确保用户能看到或定位当前活动会话。
3. 一级节点即环境节点右侧展示折叠/展开 icon。
4. 用户点击环境节点右侧 icon 时，可以折叠或展开该环境下所有二级节点。
5. 优化会话列表初始可读性，降低大量会话时的滚动负担。

## Non-goal

1. 不改变后端 session tree 数据结构或 API。
2. 不重新设计会话列表整体信息架构。
3. 不改变会话、目录、环境的创建、启动、停止、删除等业务行为。
4. 不引入新的搜索或筛选能力。
5. 不改变 active session 的选择逻辑和状态判定来源。

## User scenarios

1. 用户打开界面时，如果某个目录下没有活动状态会话，该目录默认收起，减少列表高度。
2. 用户打开界面时，如果某个目录下存在活动状态会话，该目录应保持展开到能展示活动会话的状态，避免用户误以为当前无活动。
3. 用户希望快速收起某个环境下所有目录/会话时，可以点击环境节点右侧的折叠 icon。
4. 用户希望查看某个环境下所有二级节点时，可以点击环境节点右侧的展开 icon。
5. 用户在展开或折叠环境后，已有会话选择、新建会话和会话状态展示仍保持可用。

## Acceptance

1. 页面初次加载会话列表时，没有活动状态会话的目录默认折叠。
2. 页面初次加载会话列表时，有活动状态会话的目录默认展开，活动会话仍可见或可直接定位。
3. 每个环境一级节点右侧展示清晰的展开/折叠 icon，并能反映当前展开状态。
4. 点击环境一级节点右侧 icon 后，该环境下所有二级节点统一展开或统一折叠。
5. 展开/折叠操作只影响对应环境，不影响其他环境节点的展开状态。
6. 该交互不引入横向滚动，不遮挡环境名称、状态或已有操作入口。
7. 浅色/暗色主题下 icon 可见性和 hover/active 反馈正常。
8. active session 的选中状态、会话状态颜色、目录/会话操作入口保持现有语义。
9. 空状态、加载态、无可用环境状态保持现有语义。

## Open questions

暂无需要用户确认的未决事项。

## Decisions

1. 采用 light / 轻量模式推进，仅维护 requirement 与 verification 文档。
2. 默认折叠规则以“目录下是否存在活动状态会话”为依据。
3. 环境节点右侧 icon 的作用范围限定为当前环境下所有二级节点。

## Risk

1. 如果当前前端状态管理已经记录用户手动展开状态，需要避免刷新或数据更新时被默认折叠逻辑反复覆盖。
2. 如果 active session 位于深层节点，需要确认默认展开逻辑足以让活动会话可见。
3. 批量展开/折叠二级节点时，需要避免破坏已有 tree 组件的选中、键盘导航或虚拟滚动行为。

## User review notes

- 2026-06-16: 用户提出会话列表面板可能滚动，希望优化为界面加载时无活动会话默认折叠，并在环境节点右侧提供折叠/展开 icon，控制展开或折叠所有二级节点。
- 2026-06-16: 用户反馈过多 watch 是坏味道，要求减少状态同步复杂度。
- 2026-06-16: 用户进一步澄清默认规则应聚焦目录：有活动状态会话的目录默认展开，没有活动状态会话的目录默认折叠。
- 2026-06-16: 用户反馈刷新后存在 `status: "running"` 的会话，但页面中对应目录没有展开；默认展开判断应基于会话状态，而不是仅依赖当前选中的 `activeSessionId`。
