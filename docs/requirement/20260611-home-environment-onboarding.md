# 首页环境引导轻量范围说明

Review status: Accepted

## Goal

当用户尚未设置或检测到任何可用运行环境时，主页不再显示会话列表和空终端，而是显示环境配置引导。

主页根据环境就绪状态分流：

- 任一运行环境可用时，进入 `/session`。
- 没有可用运行环境时，停留在主页并展示三种运行环境选择。
- 现有会话和终端主界面迁移到 `/session`。

未就绪主页需要展示 Windows/Cygwin、Windows/WSL、Linux 三种运行环境入口。用户点击某个入口后，进入环境管理页对应配置位置。

未就绪主页还需要展示关于如何配置运行环境的链接，点击后进入 `/help`，当前帮助内容显示“即将到来”/“Comming Soon”。

## Non-goal

- 不在主页内承载完整环境配置表单。
- 不在主页点击环境卡片时直接执行环境检测。
- 不新增首次启动弹窗向导。
- 不改变现有运行环境模型或支持范围。
- 不引入默认运行环境概念。

## Acceptance

- 当没有任何可用运行环境时，访问主页展示环境引导，而不是会话/终端界面。
- 当任一运行环境可用时，访问主页进入 `/session`。
- `/session` 承载现有会话管理和终端主界面。
- 未就绪主页展示 Windows/Cygwin、Windows/WSL、Linux 三种运行环境选择。
- 点击某个运行环境选择后，进入环境管理页对应配置位置。
- 未就绪主页提供可见的配置说明链接，点击后进入 `/help`，帮助页显示“即将到来”/“Comming Soon”。
- 未就绪状态下不应引导用户新建会话到不可完成的流程。

## Decision

- 本次前端路由和环境就绪状态管理使用 vue-router 与 Pinia，不继续扩展 App.vue 内的手写路径状态。

## Risk

- “任一运行环境可用”的判定需要与现有环境检测状态保持一致，避免主页和环境管理页状态不一致。
- 配置说明链接需要指向稳定、可维护的位置；如果文档尚不存在，需要先明确链接目标或补齐文档。
- 路由迁移到 `/session` 后，需要避免旧入口、刷新和返回行为出现空白页或错误跳转。
