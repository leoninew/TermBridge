# 终端 tab 上下文命名

- Flow mode: light
- Stage: Requirement
- Review status: Accepted
- Date: 2026-06-14

## Goal

当前终端 tab 只显示会话名称，多个目录下存在同名会话时容易重复、难以区分。终端 tab 名称改为使用当前会话列表上目录节点显示的名称与会话名称组合，让用户在 tab 区域能直接识别会话所属目录上下文。

## Non-goal

1. 不改变会话真实名称、创建逻辑、后端 session 数据结构或 `.termbridge/sessions.json` 存储格式。
2. 不重新设计终端 tab 布局、拖动排序、关闭按钮、active 状态或创建 tab 入口。
3. 不改变左侧会话列表目录节点显示名称的计算规则。
4. 不改变 iframe title、底部 workspace 路径展示或会话详情字段，除非实现中发现 tab title 必须同步以保持可访问性。

## Acceptance

1. 终端 tab 文本使用“当前会话列表上目录节点显示的名称 + 会话名称”的组合。
2. 当不同目录中存在相同会话名称时，tab 文本能通过目录节点显示名区分。
3. 目录节点显示名应复用当前会话列表的显示逻辑：同名目录按需要增加上级路径片段以避免目录节点本身重复。
4. tab 的 `title` 提示仍保留完整 workspace 路径信息，或提供不低于当前可辨识度的路径提示。
5. tab 切换、关闭、拖动排序、创建新会话入口和 active tab 状态保持现有行为。
6. 变更应尽量限制在前端显示层，不引入新的后端接口或持久化字段。

## Risk

1. 当前目录节点显示名计算逻辑位于会话列表组件内，终端 tab 组件需要复用或等价实现，存在重复逻辑风险。
2. tab 可用宽度有限，组合名称可能更长，需要保持 truncate 行为，避免挤压关闭按钮或创建按钮。
3. 如果 tab 当前仅接收扁平 `sessions`，需要确认是否能从已有 session 字段推导与左侧目录节点一致的显示名。

## User Review Notes

- 2026-06-14: 用户通过 SpecFlow 轻量模式提出：当前终端 tab 名可能重复，使用当前会话列表上目录节点显示的名称 + 会话名称作为 tab 名称。
