# 会话侧边栏两级分组与目录名消歧

- Flow mode: standard
- Stage: Requirement
- Review status: Accepted
- Date: 2026-06-14

## Background

当前左侧会话面板把运行环境作为树型节点的一层，目录节点又显示完整目录路径。随着会话目录数量增多或路径变长，侧边栏主要空间被环境层级和长路径占用，影响快速浏览和定位会话。

此前已对路径截断、sidebar 拖宽、状态颜色、顶部/底部样式做过优化，但信息结构仍然偏“完整路径管理视图”，而不是“日常会话导航视图”。本需求聚焦调整左侧会话面板的信息层级和目录展示策略，让用户更快识别项目目录和会话状态。

## Goals

1. 将左侧会话面板从“环境节点 + 目录节点 + 会话节点”的三层树型感知，调整为“固定环境分组 + 目录树内容”的两级视觉结构。
2. 环境作为固定分组展示，不作为可折叠树节点参与树型交互。
3. 目录节点默认显示目录名，减少完整路径对横向空间的占用。
4. 当同一环境内存在同名目录时，向上补充父级路径用于消歧，直到可区分为止。
5. 保留完整路径可访问性，避免紧凑显示导致用户无法确认实际目录。
6. 保持现有会话选择、新建会话、目录操作、会话状态展示等核心行为不倒退。

## Non-goals

1. 不重新设计后端 session tree 数据结构或 API。
2. 不恢复或重新实现目录浏览器的自动滚动/定位功能。
3. 不把目录节点改为始终两行展示完整路径副标题；除非后续验证证明动态消歧不足以识别目录。
4. 不扩大 sidebar 最大宽度或重做整体布局框架。
5. 不改变环境管理、快捷方式管理页面的信息架构。

## User Scenarios

1. 用户打开会话页面时，可以按固定环境分组浏览目录，不需要先理解或展开环境树节点。
2. 用户查看常见项目目录时，优先看到短目录名，例如 `term-bridge`，而不是完整绝对路径。
3. 用户在同一环境下有多个同名目录时，可以看到补充后的路径片段，例如 `mywork/term-bridge` 与 `sandbox/term-bridge`，从而区分它们。
4. 用户需要确认完整路径时，可以通过 tooltip 或等效弱信息入口查看完整目录路径。
5. 用户使用搜索框时，即使界面只显示短目录名，也仍然可以按完整路径搜索目录。
6. 用户在目录节点上新建会话、删除目录，或在会话节点上启动/停止/删除会话时，操作入口和行为保持可用且不被紧凑显示遮挡。

## Acceptance Criteria

1. 会话面板中每个可用环境以固定分组形式展示；环境分组不表现为可折叠树节点。
2. 环境分组下直接展示该环境的目录节点；目录节点下展示会话节点。
3. 目录节点默认 label 使用目录 basename。
4. 同一环境内目录 basename 唯一时，不显示额外父级路径。
5. 同一环境内存在重复 basename 时，重复项逐级向上补充父级路径片段，直到同环境内可区分。
6. 如果补充父级后仍不能区分，继续补充更上层路径；最终必须能区分同环境内不同完整路径。
7. 不同环境之间的同名目录不互相触发消歧，因为环境分组本身已经提供上下文。
8. 目录节点仍保留完整路径可查看能力，例如浏览器 tooltip 或同等低干扰方式。
9. 搜索仍按完整目录路径匹配，而不是只按当前展示 label 匹配。
10. 当前 active session 的选中状态仍能正确定位并展示在对应环境分组与目录节点下。
11. 新建会话逻辑仍使用当前选中节点的 host/workspace 上下文；固定环境分组不应破坏已有 create context 行为。
12. 目录节点的 hover 操作区不应与目录 label 重叠，也不应引入横向滚动。
13. 空状态、加载态、无 ready environment 状态保持现有语义。
14. 视觉上应延续近期会话面板样式：紧凑、弱化管理后台感、适配浅色/暗色主题。

## Decisions

1. 环境分组固定展示，不放入树型折叠层级。
   - Why: 环境是高层上下文，不应和用户日常选择的目录/会话竞争树型层级空间。
2. 目录 label 采用“目录名优先 + 必要时父级消歧”。
   - Why: 日常识别项目通常依赖目录名；完整路径只在冲突和确认时需要。
3. 消歧范围限定为同一环境内。
   - Why: 环境分组已经提供跨环境上下文，跨环境同名目录不需要互相拉长 label。
4. 搜索继续基于完整路径。
   - Why: 展示压缩不应降低定位能力，尤其是用户记得父目录或路径片段时。

## Risks / Assumptions

1. 动态消歧 label 可能在路径非常相似时变长；需要保留截断和 tooltip，避免重新引入横向滚动。
2. 固定环境分组可能使没有目录的 ready environment 是否展示成为视觉取舍；默认以现有 session tree/过滤结果为准，具体展示细节可在计划阶段结合现有空状态决定。
3. Reka Tree 当前负责键盘/选中/展开行为；将环境移出树型层级时，需要在计划阶段确认目录和会话节点的交互不受影响。
